## 6. Deviations from the blueprint

The per-module lists are in each report's "Deviations" section. The ones that matter:

1. **Formats and protocol.** None: §1, §6 and §7 are implemented byte for byte.
   - The Rust prover and the Lean `P` agree (KAT, §5).
   - The Rust prover's interpretations A1–A8 (`rust-prover.md` §4) fix the readings the
     blueprint left open: row 512 removed from `A0, B0`; column openings in squeeze order; the
     variable order. The Lean side matches them.
2. **Circuit** (`blake2s-r1cs.md`). The constant rows are gates (BP-M3 (a)). `BlockR1CS` keeps only
   the Boolean matrices. The generic form type is a second program next to leanerVM's. The closed
   circuit terms are `noncomputable`, with the computable `@[never_extract] chainBlockAt` for the
   dump.
3. **Spartan** (`spartan-protocol.md`). `verify` takes parsed messages and absorbs their
   re-encoding, which is injective. The check is `g(0)+g(1)`, the same in characteristic 2.
4. **Ligero and proximity** (`ligero.md`, `rs-proximity.md`). `Proximity.lean` is not a port of
   ArkLib's `AHIV22`. It is an independent proof of the same statement, with ArkLib as a guide.
   Openings are absorbed nowhere (§6.2).
5. **Merkle and transcript** (`oracle-merkle-transcript.md`).
   - L-M2 needs `¬ Collision L`.
   - `StateHit` uses `i ≤ j`, not §9.1's `i < j`.
   - L-M4 cuts at `absorb(root)`, because the blueprint's wording is false (a counterexample is
     given there).
   - L-M3 comes in two forms.
6. **Sumcheck and ring switching** (`mle-sumcheck-ringswitch.md`). The modules are generic. L-S1
   drops a hypothesis, so it is stronger. `ybasis` is used in independence form. The `c_k` table is
   built by concatenation.
7. **Knowledge soundness** (`soundness-ks.md`, `soundness-spartan.md`, `soundness-pcs.md`).
   - The modules are split.
   - `condCount` takes an explicit round length.
   - **`δ_i` uses bit planes**, a correction to the blueprint's row indexing.
   - `EvalsOK` holds for `chainEvals` only (midreview m1).
   - The witness split is a hypothesis, discharged by `Chain`.
8. **Top level** (`verifier-top.md`, `decode.md`, `submission-infra.md`).
   - The SNARK is a parameter (`LeafVerifier`).
   - The node codec works by byte offsets (`nodeParse`, `nodeParse_eq`), added beyond the
     blueprint for `T_V` (midreview M2).
   - `Facts.queries` is guarded by `n ≤ chainCap` (midreview M1).
   - `P` builds nodes with `encodeNodeB`.
9. **Rust prover** (`rust-prover.md` §6). The crate is in the root, not `native/`. There is no
   `blake2` or `rayon`. Two commands are extra. The prover uses the faster algorithm, with the
   same bytes.
10. **The field.** It is word-level, with proofs of equality to CompPoly (`FIELD.md`). The final
    review's nanoda finding led to a structural rewrite of `F.spread_getLsbD` (§9, "Fix pass").

## 7. Scope: what R1 is and is not

- **Succinct at the leaves only.** The nodes are witness-sending ([D-3], BLUEPRINT §0). A node
  proof embeds both children, so the root proof is linear in the leaf count: 575 112 B at
  `r = 2`, `n = 16`. The entry is **not recursive**: nothing verifies a SNARK inside a SNARK.
- **Unranked, by `proofCap`.**
  - At the ranked size (`r = 8`, `n = 2^14`) a single leaf proof is already 1.46 MB > `proofCap`
    = 1 MiB.
  - A node with 256 leaves cannot fit at any `n`: §0 fact 1 needs leaves under 4 KiB.
  - Leaves fit `proofCap` up to `n = 4096`.
- **What is and is not measured.** The board-T tree run and the root check at the ranked size
  are **not measurable**: the proofs exceed `proofCap`, so `Vb` rejects them on size.
  - The native prover was measured on single leaves up to `n = 2^14` (7.4–8.0 s; verified
    natively with `check-leaf`, which skips the cap).
  - The smoke tree was measured at `r = 2`, `n = 16`.
  - The root check was measured at the smoke size only.
  - No `T_tree` or `T_root` for board T exists.
- **The node branch evaluates `blake2sOracle`** on the children (`check`, for `Rel` through `Vb`).
  It compares no oracle answer: it accepts exactly when `Rel` holds, which is S2a's pattern. The
  O-25 intake review should be told.
- **The `T_V` margin** on the smoke root is 0.3–1.0 s on this VM. The DoS behaviour is that of §5.
