## 4. Finding: the library's witness-sending verifier fails the canaries

`RecursionFast.Library.WitnessSending.check` requires the canonical encoding only in the node
branch. In the leaf branch it accepts whenever `decode π` is a leaf witness of the statement.
`decodeWit` reads words 0–5 of a leaf and ignores the rest, and `packBytes` zero-pads the last
word, so:

- a leaf proof with one byte appended (49 bytes, 7 words) decodes to the same leaf;
- a leaf proof with its last byte removed (47 bytes) decodes to the same leaf whenever the top byte
  of the length word is zero: kernel-checked at `n = 16` (`lib_leaf_truncated`); the argument holds
  for every `n < 2^56`, so for every `n ≤ chainCap`.

Kernel-checked: `lib_leaf_appended`, `lib_leaf_truncated`, `lib_check_appended`,
`lib_check_truncated`. Both are canaries of §6.3 step 7 ("the first 8 proofs of each kind must be
rejected with one appended byte, with the last byte removed"), so the library's `submission` would
fail the benchmark run. The certificate is unaffected (the extra proofs are valid proofs of true
statements). The entry's `check` adds `encode (.leaf s n) = π` to the leaf branch. Since
`Rel S.Vb` is about the submission's own instantiated verifier, the strict check must be used for
the children too, so `check` and its soundness and completeness proofs are the entry's.
**Suggested core fix** (one line in the leaf branch, plus the existing proofs): the orchestrator's
decision.

## 5. Deviations from BASELINE-TASK (whose sketches predate S1), and from the design

1. **Proof format.** Not the brief's LEB128 `ser` (§4.1): the library's `encode`, whose bytes are
   the extractor output words of S1's `decodeWit` format (V3-S1-A7, A22). Sizes: leaf 48 bytes
   (brief: 36), root 456 bytes at `r = 2` (brief: 339) and 34,728 bytes at `r = 8`, `n = 2^14`
   (brief: 26,555). `n` is a 64-bit word: S1 caps `n ≤ chainCap = 2^20` (V3-S1-A20), so every
   witness of `Rel` fits and completeness holds without an unbounded encoding.
2. **`fuel` is `fuel t`** (tape words, V3-S1-A21), not `fuel p l`; it is the constant 8.
3. **The image is not a validating copy loop** (brief §4.5): S1's lenient `decodeWit` (A22) lets
   the library's 8-instruction image output the proof's words in place. `ImageComputes` is the
   library's theorem; the entry proves no machine lemma.
4. **`check` is well-founded recursion on `π.size`** (the library's pattern), not `vcore` with an
   explicit fuel; there is no fuel-independence lemma to prove.
5. **The key lemma's shape.** The brief's `Vb c π = true ↔ π.size ≤ proofCap ∧ ∃ w, decode π =
   some w ∧ Rel S.Vb c w` is false for a strict verifier (a non-canonical proof that decodes to a
   witness is rejected). Proved instead: `Vb_eq`, `check_sound` (→), `check_canonical` (accepted
   proofs are canonical) and `check_encode` (← for the canonical proof of every witness).
6. **Strict leaves and per-level linear-time decoding** are additions (§4 above; §6 below).
7. **Files.** One `BaselineV3.lean` instead of Format/Verifier/Extractor/Security (the format,
   the extractor and the image proof are the library's); `BaselineV3Controls` for `Negative`;
   `BaselineV3Solution` for `Solution`; `BaselineV3Run` added. No committed `Axioms.lean` and no
   `check-hygiene.sh`: `check.sh` generates the axiom file from the sources and inlines the
   hygiene scan. (The interim organiser files first added here moved out of the root in the fix
   pass, M1.)
8. **The challenge stub is organiser-side and interim**: on the scratch core branch
   `v3/s2-interim-harness` (fix pass, M1), not in a core pull request (S2a has no core half). Its `declared` renders `ε` as `((a : ℝ≥0) / b)` and is therefore `noncomputable`; the
   declared fuel is affine, `fuel_base + fuel_per_word · t`. The claim schema (`image`, `error`,
   `qV`, `fuel_base`, `fuel_per_word`) is this entry's proposal.
9. **The harness.** The core's `scripts/harness.sh` is not at the pin; the interim
   `scripts/harness-local.sh` (scratch core branch) follows
   its v2 order with the tools at the pin and a locally generated allowlist and manifest (§1 of the
   headline). The badge executables, the benchmark run, the emulator liveness check and the
   `treeRoot` known-answer test (S3) did not run.
10. **The `KState` is not copied from `Controls/Security.lean`**: the entry defines its own (`good :=
    True`, `bad := False`) and imports `bounded_of_not_bad` from the library, which an entry may
    import.
11. **Prover file formats** (`leaves.json` = `{"n", "starts"}`; `proofs/L<i>.bin`,
    `proofs/N<level>_<j>.bin` with levels `1 … r`, `root.bin`; `.stmt` as 64 hex digits or 32
    raw bytes) are this entry's; S3 fixes them.

## 6. Decoding cost: per level linear, overall `O(|π| · depth)`

The contract's `packBytes` computes word `j` as `(b.drop (8 * j)).take 8`, and `bytesAt` reads
each byte through `List.getD` on the word list: both compile to quadratic code. The entry's first
verifier (strict `check` over the library's `decode`) took **563 s** to reject a uniformly random
1 MiB proof (`logs/V3-S2/dos-unfiltered/run.log`, the binary of that version beside it), past
`verify_s = 60 s`: it would fail the DoS column (§6.2). `packFast` (8 bytes at a time), `bytesAtF` (through an
array) and `decodeF`/`encodeF` are proved equal to the library's functions (`packFast_eq`,
`bytesAtF_eq`, `decodeWitF_eq`, `decodeF_eq`, `encodeF_eq`); `check` runs them, and `check_eq`
restates `check` with the library's functions, which every proof uses. Random proofs now reject in
at most 0.28 s, adversarially shaped 1 MiB proofs under the root digest in at most 1.25 s
(`logs/V3-S2/fix/check/smoke.log`).

**The verifier as a whole is not linear** (V3-S2a-M2). Each node decodes, re-encodes and compares
its whole subproof, and `bytesAtF` copies each child, before recursing, so the decoding work is
`O(Σ over the nodes of the subproof size)` = `O(|π| · depth)`. Measured by the review on valid
"caterpillar" proofs (each node: a deeper left child and a zero-step leaf, no chain work): depth
250, 34,048 B: 2.68 s; 500: 11.63 s; 1,000: 49.56 s; 2,000, 272,048 B: **212.64 s**, ×4 per
doubling, past `verify_s = 60 s` (`logs/V3-S2/review/caterpillar.log`). This is a property of this
unranked entry's DoS behaviour: under the runner's root digest such a proof needs a hash preimage
(the honest shape has depth `r`), and the DoS column draws random proofs; it matters for `verify`
on a statement the prover chose. Not fixed: a linear verifier over byte offsets into one buffer,
proved equal to `check`, is a larger proof than this baseline warrants (open question 6).

## 7. Open questions for the orchestrator

1. **The library's leaf malleability** (§4): fix the library's `check` in the core (then the entry
   could drop its own `check` only if the library's decoding were also fast), or keep the entry's?
2. **Quadratic compiled `packBytes`/`bytesAt`** in the contract: every entry that decodes with
   them inherits the cost. A library-level linear-time twin (as here) is cheap; the contract's
   definitions need not change.
3. **Gate rule 4's `badgeFields` are v2's** (`Submission`: `P`, `cfg`). Rule 4 checked the whole
   constant ("`submission`: compiled code"), not `V`, `P`, `E` one by one; the baseline passes
   because `submission` compiles as a whole. S3 should list the v3 fields (`V`, `P`, `E`, `img`) for
   submissions with a noncomputable `ε`.
4. **Stub and claim schema** (deviation 8): S3 decides the v3 stub, the renderer's kinds (an `ℝ≥0`
   rational makes `declared` noncomputable) and the shape of the declared fuel.
5. **Calibration**: on this VM `T_triv ≈ 20.9 s ≥ 5 · T_V = 10 s`. The reference machine (O-6)
   replaces the number.
6. **A linear verifier** (M2): worth it for the baseline, or only if a later entry needs a
   witness-sending sub-verifier? Not done here.
7. **The allowlist scope** (review m8): v2's closure includes `RecursionFast.Controls`, so gate
   rule 6 does not enforce "an entry imports no Controls". Drop `RecursionFast.Controls` from the
   closure in S3 if the convention is meant to be enforced.
8. **The S2 core half** (allowlist and manifest regenerated in the core, the v3 stub, the v2
   baseline removed from the core) is still to do. Here the allowlist (10,777 modules) and the
   manifest (34,305 files) were generated under `logs/` only.
